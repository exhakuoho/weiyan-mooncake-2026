# Apps Script（報名資料接收端）

這是 Google Apps Script 專案「2026 3D客製月餅工作坊｜報名連動」的原始碼備份。
Apps Script 本身沒有版控，這份檔案是唯一的歷史紀錄——**改了 Apps Script 就要同步更新這裡**。

- 專案：script.google.com → 所有專案 →「2026 3D客製月餅工作坊｜報名連動」
- 寫入目標：試算表「2026 3D客製月餅工作坊｜報名管理」的「報名資料」分頁
- 部署：網頁應用程式，存取權「所有人」，網址就是 `GOOGLE_SHEETS_WEBHOOK_URL`

## 指令碼屬性

| 屬性 | 用途 |
|---|---|
| `WEBHOOK_TOKEN` | 與網站的 `SHEETS_WEBHOOK_TOKEN` 對招，擋掉外部亂灌資料 |
| `NOTIFICATION_EMAIL` | 新報名通知信的收件人 |

## 兩個刻意的寫法，不要「順手改掉」

1. **原始碼不含反斜線跳脫與反引號**（換行用 `NL_`、雙引號用 `q_()`、
   HTML escape 用 `split().join()` 而非正規表達式）。因為這份程式碼是透過瀏覽器
   自動化整段注入編輯器的，模板字串會把 `\n`、`\d` 這類跳脫吃掉，導致注入後的程式碼
   與這裡的版本不一致。要手動貼上當然沒差，但保持這個限制才能重複自動化。
2. **`sendRegistrationNotification_` 永遠不 throw**，失敗一律回 `false`。
   寄信發生在 `appendRow` 之後——資料已經進表了，這時回報失敗會讓使用者
   以為沒報到而重送，造成重複報名。API 回應的 `emailSent` 只作為記錄用。

## 改完之後

要重新部署才會生效：部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署。
用「編輯現有部署」才會保留原本的 `/exec` 網址；按「新增部署作業」會產生新網址，
那樣網站的 `GOOGLE_SHEETS_WEBHOOK_URL` 就要跟著換。
